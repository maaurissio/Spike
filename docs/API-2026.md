# API-2026 — Documentación vigente y fuentes complementarias

> Estado técnico: verificado 2026-08-25; alcance local actualizado por ADR-014 el 2026-08-28. El roster base está habilitado en el prototipo local. ADR-013 y `ROSTER-POLICY.md` conservan por separado la advertencia oficial para distribución.

## 1. Matriz de fuentes (vigencia 2026)

| Fuente | Tipo | Autenticación 2026 | Rate limit vigente | Privacidad | Uso en VTracker |
|---|---|---|---|---|---|
| **Local Client API** (`valapidocs.techchrism.me`) | No oficial, del cliente en vivo | Lockfile `riot:{password}` + `accessToken`/`token` locales (`token` = entitlement JWT; expiran ~1h) | Sin rate limit documentado para localhost | `Incognito` permanece anónimo; IDs efímeros | Contexto, fases y roster base local (ADR-014) |
| **Riot Oficial VAL-*** (`developer.riotgames.com/apis`) | Oficial | Producción key + RSO (OAuth `auth.riotgames.com/authorize?client_id=...&scope=openid offline_access`) | Documentado por endpoint; producción requiere aprobación | Requiere opt-in para mostrar stats personales; scouting prohibido; no ver IDs históricos de otros ocultos | Opcional: leaderboards, contenido, `matchlists` remoto cuando juego cerrado |
| **HenrikDev Unofficial** (`api.henrikdev.xyz` / `docs.henrikdev.xyz`) | No oficial sobre Ingame API | Basic 30 req/min instantánea, Enhanced 90 req/min (Discord #get-a-key) | `X-Cache-Status: HIT/MISS` + `X-Cache-TTL` | Pide consentimiento del usuario | Alternativa remota si local no disponible (sin lockfile) |
| **Valorant-API.com** (`dash.valorant-api.com`) | No oficial estático | Sin auth | Sin límite relevante | Assets públicos | Iconos: agentes, mapas, armas, temporadas |
| **Tracker.gg (Parse)** | Proxy comercial | `X-API-Key`, Free 5 req/min (200 créditos/mes) → Company 500 req/min | Créditos 1-10 por llamada | Perfiles públicos de tracker.gg | No necesario (usa local para live) |

## 2. Local Client API — endpoints vigentes verificados

Base URLs (ver `valapidocs: Common Components` + `ccjakje/val-local-api`):

```
local:    https://127.0.0.1:{port}              // lockfile, self-signed → bypass en Rust
pd:       https://pd.{shard}.a.pvp.net
glz:      https://glz-{region}-1.{shard}.a.pvp.net
shared:   https://shared.{shard}.a.pvp.net
```

Componentes comunes (actualizados 2026):

* **Lockfile:** `%LocalAppData%\Riot Games\Riot Client\Config\lockfile` → `name:pid:port:password:protocol`
* **PUUID:** vía `RNet_FetchSession` local o `RSO_GetPlayerInfo` remoto.
* **Tokens:** `GET https://127.0.0.1:{port}/entitlements/v1/token` → `accessToken` (bearer) + `token` (entitlement JWT), `issuer`, `subject(puuid)`. Expiran ~1h.
* **Región/Shard:** `RiotClientSession_FetchSessions` (`-ares-deployment=`), log `ShooterGame.log`, o preguntar al usuario. Tabla 2026: `latam|br|na→na`, `eu→eu`, `ap→ap`, `kr→kr`, `na` compatible `na/pbe`.
* **ClientVersion:** `ShooterGame.log` / `Sessions` / `https://dash.valorant-api.com/endpoints/version`.
* **ClientPlatform:** base64 de `{"platformType":"PC","platformOS":"Windows","platformOSVersion":"10.0.19042.1.256.64bit","platformChipset":"Unknown"}` → `ew0KCSJwbGF0...`.
* **pregameMatchId:** WebSocket `OnJsonApiEvent_riot-messaging-service_v1_message` URI `/ares-pregame/...` o `Pregame_GetPlayer`.
* **coregameMatchId:** mismo WebSocket con `/ares-core-game/...` o `CoreGame_FetchPlayer`.
* **partyId:** WebSocket `OnJsonApiEvent_chat_v4_presences` o `PRESENCE_RNet_GET_ALL` / `Party_FetchPlayer`.

### 2.1 Local (127.0.0.1) — vigentes

| Endpoint | Método | Uso VTracker |
|---|---|---|
| `/help` | GET | Descubrir endpoints/eventos/tipos del cliente local |
| `/swagger/v3/openapi.json` | GET | Swagger/OpenAPI local para inspección |
| `/entitlements/v1/token` (RSO_RNet_GetEntitlementsToken) | GET | Tokens |
| `/product-session/v1/external-sessions` | GET | Sesiones locales; versión y argumentos de arranque |
| `/riotclient/region-locale` | GET | Región y locale del Riot Client |
| `wss://riot:{password}@localhost:{port}` | WSS | Eventos en vivo: pregame/core-game, `chat_v4_presences` (partyId) |

Helpers Rust existentes (val-local-api, wrapper Techchrism): ya abstraen `ValorantClient::connect()` auto-leyendo lockfile, SSL bypass, `pregame_player/match`, `coregame_player/match`, `match_history`, `match_details`, `mmr`, `names` y stream SSE `LogWatcher` (`round_ended`, `bomb_interaction`, `player_died`).

### 2.2 PVP — vigentes

* `GET /mmr/v1/players/{puuid}` → MMR + historial (shard `na/eu/ap/kr/pbe`). Verificado 2026-08-25 `valapidocs: GET Player MMR`.
* `GET /match-history/v1/history/{puuid}` / `GET /match-details/v1/matches/{id}` (implícitos vía puuid/matchId) — vía wrapper local también: `/pd/history`, `/pd/match/{id}`. El detalle incluye el `accountLevel` observado en esa partida; VTracker conserva solo el más reciente de las cinco Ranked como respaldo visual.
* `PUT /name-service/v2/players` → resolver puuids visibles; cuerpo JSON `string[]`.

### 2.3 GLZ — vigentes

* `GET /pregame/v1/players/{puuid}` → preGame matchId.
* `GET /pregame/v1/matches/{id}` → Agent Select: equipo aliado disponible, rango, agente en selección y `PlayerIdentity.AccountLevel`; el rival se incorpora desde Current Game al terminar la selección.
* `GET /chat/v4/presences` → relación efímera jugador/party desde `private`; VTracker descarta PartyID y solo conserva etiquetas `Grupo A/B` o `Solo`. La TUI marca con un `•` del mismo color a cada miembro de una premade, sin exponer el identificador.
* `GET /core-game/v1/players/{puuid}` / `GET /core-game/v1/matches/{id}` → partida en curso (mapa, modo, equipos).

### 2.4 Shared — vigentes

* `GET /account-xp/v1/players/{puuid}` (nivel), `GET /playerloadout`, etc. (viaje futuro).

## 3. Riot Oficial — vigente 2026-03-07 (política actualizada)

**Registro obligatorio** aunque no uses sus endpoints. Funciones nuevas deben auditarse. **Monetización:** no apuestas.

**Oficiales Valorant (developer.riotgames.com/apis) — sin cambios 2026:**

| API | Método | Descripción |
|---|---|---|
| `VAL-CONTENT-V1` | `GET /val/content/v1/contents?locale=...` | Contenido + filtro por locale |
| `VAL-MATCH-V1` | `GET /val/match/v1/matches/{matchId}` | Match por ID |
| | `GET /val/match/v1/matchlists/by-puuid/{puuid}` | Matchlists por puuid |
| | `GET /val/match/v1/recent-matches/by-queue/{queue}` | Recientes por cola |
| `VAL-RANKED-V1` | `GET /val/ranked/v1/leaderboards/by-act/{actId}` | Leaderboards |
| `ACCOUNT-V1` | `GET /riot/account/v1/accounts/by-riot-id/{name}/{tag}` etc. | PUUID ↔ Riot ID |

**Política reverificada 2026-08-28:** Personal Key applications *currently not supported*; *scouting* de rivales antes de la partida no aprobado; apps solo personales no aprobadas; overlays que den ventaja en tiempo real no aprobados; tracking de tienda no existe. **RSO obligatorio** para mostrar estadísticas personales y requiere production key/aplicación aprobada. También se prohíbe identificar o analizar a jugadores que ocultaron deliberadamente su identidad. Fuentes: [VALORANT policies](https://developer.riotgames.com/docs/valorant), [General Policies](https://developer.riotgames.com/policies/general) y [OAuth Client Documentation](https://support-developer.riotgames.com/hc/en-us/articles/22897607341075-OAuth-Client-Documentation).

## 4. Valorant-API.com — estático (vigente)

`https://valorant-api.com` / `https://dash.valorant-api.com` — sin auth, dashboards por `Agents/Buddies/Cards/Currencies/Gamemodes/Maps/Seasons/Titles/Weapons`. Uso: iconos de agentes/mapas para la TUI (Ratatui no necesita imágenes, pero sí UUID → nombre). Comprobado 2026-08-25.

## 5. HenrikDev — vigente v4.6.1 (2026)

**Base:** `https://api.henrikdev.xyz` / `eu.api.henrikdev.xyz` (evita peering Telekom). **Auth:** Basic 30 req/min, Enhanced 90 req/min (Discord). **v4** añade `?api_key=` alternativo y headers `X-Cache-Status/TLL`.

Endpoints nuevos/streamlined: `/valorant/v2/account/{name}/{tag}`, `/valorant/v3/leaderboard/{region}/{platform}?start_index&size`, `/valorant/v3/mmr/{region}/{platform}/{name}/{tag}`, `/valorant/v4/match/{region}/{platform}/{id}` y `/valorant/v4/matches/{region}/{platform}/{name}/{tag}`. **Deprecados** av1 lifetime/mmr/leaderboard (3 meses tras v4).

**Para VTracker:** solo como fallback si el local no está disponible y el usuario da su Henrik key; no primario.

## 6. Lo que no existe (evita diseño muerto)

* `Online store tracking` (política Riot: tecnología no existe en API).
* Personal Key nueva (no soportada en 2026).
* Un endpoint único que dé kills/muertes en vivo por ronda dentro de la ronda en curso — solo post-partida via `match-details`.
* `val/status` para live — solo platform-data.

## 7. Plan de uso en VTracker (sin BD, durante la partida)

* **Prototipo actual:** lockfile → tokens → `LiveMatchSource` (contexto + roster base y Name Service visible) + `PlayerProfileSource` (MMR/history propios) + `MatchDetailSource` (rondas propias post-partida). El enriquecimiento histórico del roster aún no está conectado.
* **Oficial/Henrik:** solo si `puuid` conocido y juego cerrado, o para líderboards/contenido. Se cachea en memoria 5-15 min con `moka`/`cache-rs`; nunca en disco permanente.
* **Valorant-API.com:** pre-cargado en memoria al inicio (una vez por sesión, TTL largo) para mapear UUIDs sin red ulterior.

La vigencia técnica de las fuentes complementarias se revisó el 2026-08-25 y la política oficial el 2026-08-28. Una fuente comunitaria nunca sustituye autorización de Riot. Si una fuente falla, la app degrada con elegancia sin buscar rutas que eludan consentimiento o privacidad.
